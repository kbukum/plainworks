---
"@plainworks/state": minor
---

Neutralize `@plainworks/state`'s public surface so the store engine is no longer part of the contract. `Store`, `StoreInitializer`, `StoreSet`, and `StatePatch` are now plainworks-owned types — no Zustand type is reachable from the `.` or `./client` exports, so the default engine (still Zustand's `zustand/vanilla`) can change without a breaking change and consumers are no longer coupled to it.

The `./client` binding is now engine-agnostic and split by subpath so the bring-your-own path carries **zero dependency on the default engine**, even in a native-ESM host that cannot tree-shake: `@plainworks/state/client/supplied` exposes `createSuppliedStoreContext()` — a Provider (with a required `store` prop) plus selector hooks — from a graph that imports no `createStore`, so a consumer running their own store never loads Zustand. `@plainworks/state/client` keeps the built-in default engine via `createStoreContext(initializer, options?)` and `initialState` hydration; its Provider no longer takes a `store` override. `useStore`/`useStoreApi` drive React's own `useSyncExternalStore` over the owned `Store` seam, with both the client and server snapshots cached by selector so an allocating selector stays reference-stable across SSR/hydration reads.

Add a minimal, explicit ergonomics facade on the server-safe `.` entry: `defineStore({ state, actions })` composes an initializer from separate state and actions — `actions` is required exactly when the store declares them, and the composed `StoreShape<State, Actions>` (`Omit<State, keyof Actions> & Actions`) models an action overriding a state key soundly — and `createSelector(inputs, combine)` is a memoized derived selector (reselect-style, `Object.is` inputs) so a derived value keeps a stable reference and re-renders a consumer only when it actually changes. The owned `Store` contract now documents that snapshots are immutable (every update publishes a new state reference), which the `Object.is` snapshot caching relies on. Configuration mistakes (a context built without an initializer, a supplied Provider rendered without its `store`) throw the new `StateConfigError` (`kind: "state/invalid-config"`), distinct from `StateError`'s `state/missing-provider`. Retains the per-request factory, `useRef` Provider, and SSR isolation from the prior release.
