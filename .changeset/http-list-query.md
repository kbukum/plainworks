Add the **PostgREST list-read contract** to `@plainworks/http` — the canonical typed list-query wire plainworks defines, so the frontend speaks a typed list language a backend implementing this contract parses.

- **`buildListQuery`** serializes a typed `ListQueryParams` (`filters`, `page`/`pageSize`, `cursor`, `sortBy`/`order`, `search`, `includes`, `facets`) into the PostgREST string: `field=op.value` per filter (`status=eq.active`), `in.(a,b,c)` / `not.in.(...)` for list operators, `is.null` / `not.is.null` for presence, and a repeated key for a field carrying several filters (a range). `page` and `cursor` are mutually exclusive — supplying both is a caller fault — and cursor mode is selected by the **presence** of `cursor` (an empty `cursor=` requests the first page, so a cursor first page and a defaulted offset page 1 are never identical on the wire). A value carrying the list delimiter (`,`) or the escape char (`\`) is backslash-escaped so it round-trips; an empty-string membership value is rejected (`[]` and `[""]` would share one wire form). Field names inherited from `Object.prototype` (`toString`, `__proto__`) serialize correctly (null-prototype dictionary). A value shape that contradicts its operator is rejected as a fatal `http/request` error, never mis-serialized. The result flows through the existing URL safety, credential guard, auth injection, timeout, retry, and codec — no new transport.
- **`ListFilter` as a discriminated union** — `ScalarFilter`, `ListMembershipFilter`, and `PresenceFilter` ensure every operator carries exactly the value shape it needs; TypeScript rejects a mismatched combination at compile time.
- **Canonical operator-token contract** — the whole list-contract slice (param builder, envelope types, and the operator-token table `FILTER_OPERATOR_TOKENS` / `FILTER_OPERATOR_TOKENS_LONGEST_FIRST` / `filterOperatorFromToken`) is published as a `@plainworks/http/list` subpath, so a backend parser (e.g. `@plainworks/mocks`) consumes the same token table the builder serializes from without pulling in the fetch client; the two sides cannot drift.
- **Envelope types** — `PaginatedResult<T>` (offset: `{ data, pagination: { page, pageSize, total, totalPages }, facets? }`) and `CursorResult<T>` (cursor: `nextCursor`/`prevCursor`), decoded and schema-validated at the boundary like any other body.

The matching deterministic cache-key derivation is the L2 half of this contract, in `@plainworks/query`. `@plainworks/mocks` consumes this token contract directly, so the builder and the mock parser share one source of truth.
