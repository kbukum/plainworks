Add `@plainworks/app` (L4) — the **composition kernel** that wires the plainworks concern packages into a working whole through an **injected capability registry**. No batteries are baked into core: an app is exactly the capabilities passed in (a theme, a session, a `channel` status, `auth`, telemetry — each injected, not a hard dependency of core).

- **A capability is two halves joined by an `id`** — a **neutral server resolver** (`defineCapability`, from `@plainworks/app`, React-free) and a **client provider** (`defineProvider`, from `@plainworks/app/client`, `"use client"`). Keeping them in separate modules is what lets a server run the resolvers without pulling the provider graph into its bundle, so RSC and token-custody safety are structural, not a convention — there is no "server-runnable module that imports React" bucket to smuggle a provider through.
- **`createApp` per-request factory** — the one place the à-la-carte concern packages compose. Pure, no import-time side effects, no module-level singleton, so concurrent SSR requests each get an isolated app. It takes the **neutral resolver halves**, rejects duplicate ids with a typed `AppConfigError`, and exposes `resolve()`. Resolvers are independent, so they run concurrently — no ordering seam on the server.
- **Zero-flash SSR contract (neutral `.` entry, plain data)** — `app.resolve(context)` runs every capability's server resolver concurrently, each bounded by the request `signal` (via `@plainworks/std`'s `raceAbort`, so a pre-aborted or mid-flight signal abandons the resolver), into a JSON-serializable `AppSnapshot`; `serializeSnapshot`/`deserializeSnapshot` cross the wire so each capability's first client render matches the server. The kernel never touches a capability's React provider, so `.` runs anywhere (Node, edge, workers, RSC, React Native).
- **Headless `./client` React binding** — `AppProvider` takes the injected **provider halves** and the deserialized snapshot, orders them by each provider's **declared `dependsOn`** (a deterministic topological sort, stable tie-break on registration order; unknown or cyclic ids fail fast with `AppConfigError`), and mounts each outermost→innermost. It imports no `@plainworks/ui` and no `@plainworks/query` — a shared query client is mounted as an opt-in capability (`createQueryCapability`), not a special-cased prop. The server's resolve-only `App` never crosses the RSC boundary; only the serialized snapshot does. `useAppSnapshot` reads the composed snapshot from the subtree.
- **`AppErrorBoundary`** — a behavioral boundary with an injected fallback, a report seam, and `resetKeys` auto-recovery.
- **`@plainworks/app/testing`** — a shipped harness (`renderWithProviders`) that renders a subtree inside the real providers from the provider halves; self-contained (never imports `@plainworks/testkit`/`mocks`, starts no network mock).

The `no-app-into-ui` boundary rule (with a fixture proving it bites) keeps the kernel `ui`-free even though `ui` sits below it, and `app` joins the host-neutral portability gate.

- **Opt-in recipes (per-recipe subpaths `@plainworks/app/capabilities/{state,auth,query}`)** — thin, ejectable factories that turn a core package into a registry-ready provider half declaring its own `dependsOn`: `createScopesCapability` publishes a `@plainworks/state` scope registry (the canonical replacement for a dedicated kernel `scopes` seam — scopes stay one more capability, not a second extension point), `createQueryCapability` mounts a caller-owned TanStack client (so a data capability can sit inside the shared cache deterministically), and `createAuthCapability` bridges `@plainworks/auth`'s session store to React through `@plainworks/state`'s published `createSuppliedStoreContext`, exposing a `useSession` hook (client-reactive identity/status, never the token). Each recipe is its own subpath so it pulls in only its owner — `@plainworks/state`, `@plainworks/auth`, and `@plainworks/query` stay genuinely optional peers, and an auth-only app never loads query. Each is glue over a package's public binding — delete `app`, hand-wire the same bindings, and you lose only convenience. `ui`-free by construction; `ui`-backed batteries live in the showcase. `createAuthCapability` publishes the **client** session (login/logout reactive, the SPA path); server-resolved no-auth-flash SSR awaits auth's own server session binding.
